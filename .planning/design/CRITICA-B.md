# CRÍTICA B — Purista HIG / Acessibilidade (WCAG 2.2 AA)

Papel: crítico B. Método: Apple HIG (toque 44pt, foco sempre visível, hierarquia nunca só por cor, chrome translúcido × conteúdo opaco, sem autoplay) + WCAG 2.2 AA (1.4.3 contraste texto 4.5:1, 1.4.11 não-texto 3:1, 1.4.1 uso de cor, 2.5.8 alvo 24px mínimo / HIG 44pt, 2.4.7/2.4.13 foco, 2.2.1 temporização ajustável, 2.3.3 animação por interação, reduced-motion/transparency). Li os 8 docs completos. Sem elogios vazios: o que está certo é citado em 1 linha, o resto é defeito + valor corrigido.

## 1. Onde as regras VIOLAM HIG ou WCAG AA

### 1.1 Contrastes duvidosos / não provados
- **B-01 (01 §2.1 botão perigo dark): FALSO.** `01` trava "botão perigo: fundo `--danger #F2555A`, texto `#FFFFFF` nos dois modos (5.9:1/4.6:1)". Branco sobre `#F2555A` dá ~3.0–3.3:1 — **REPROVA AA 4.5:1**. O "4.6:1" declarado está errado. AJUSTE: dark usa texto `#1A0505` sobre `#F2555A` (~6.5:1); light mantém `#FFFFFF` sobre `#C92A30` (6.2:1, ok).
- **B-02 (01 dark `--warning = --accent`): violação 1.4.1 por projeto.** Aviso e marca com o mesmo dourado `#E8B34B` em dark significa que "dourado" quer dizer marca, aviso, foco e hover ao mesmo tempo. A regra 5 ("acompanhar de seta/sinal") existe mas é texto solto — nenhum componente trava o cue não-cor. AJUSTE: manter a coincidência **somente** com cue não-cor obrigatório travado por componente (badge warning exige ícone `TriangleAlert` + texto; delta/KPI exige `▲▼/+−`; toast/banner exige ícone). Sem o cue, o uso é vetado em review. Alternativa limpa (preferida): desdobrar `--warning` dark para `#F6A723` (contraste ~8:1 sobre `--bg-1`, matiz distinguível do accent em teste grayscale + daltanopia).
- **B-03 (`--text-3` 3.4:1/3.6:1 "só decorativo"): a isenção é usada para coisa funcional.** `01` diz que `--text-3` é só placeholder/caption/timestamp, mas `05 §1.1/§2.4` põe rótulo de grupo de navegação `11px var(--text-3)` e `02 §3.4` admite `muted` em `callout/caption`. Rótulo de grupo de nav **é funcional** (orienta varredura da sidebar) e 11px não é "large text" — reprova 1.4.3. AJUSTE: rótulo de grupo = `12px/700` em `--text-2` (7.0:1), `letter-spacing 0.08em`, uppercase mantido. `--text-3` fica restrito a placeholder, timestamp e caption com texto redundante (a info existe em outro lugar com contraste).
- **B-04 (bordas `0.08–0.16` alfa como fronteira de input): reprova 1.4.11 (3:1 para componente de UI).** `border-medium` translúcida sobre `--bg-1` não chega a 3:1. Divisória decorativa pode ficar em `subtle`, mas **fronteira de input, checkbox e borda de tab ativa** precisam de contraste. AJUSTE: idle de input usa `--border-strong`; hover idem + `border-width` estável; focus usa ring (abaixo). Documentar a isenção: "divisórias `border-subtle` são decorativas e isentas de 1.4.11; fronteiras interativas nunca usam `subtle`".
- **B-05 (contraste sobre glass não é computável e nenhum doc exige teste worst-case).** Todos os ratios declarados assumem fundo opaco, mas `surface-1/2/3` têm 50–72% de opacidade. Texto `--text-2` sobre card glass com foto/gráfico claro atrás pode cair abaixo de 4.5:1. AJUSTE: travar protocolo — (a) texto funcional sobre glass usa **somente** `--text-1` (nunca `--text-2`) quando o backdrop for variável (foto/gráfico); (b) teste de aceite com backdrop branco puro e preto puro atrás do glass; (c) se reprovar, subir glass para `--surface-2` (78%) ou cair para `--surface-solid`. Colocar isso na UAT de `01 §4`, não como "nota".
- **B-06 (`--accent-soft` claro `rgba(138,94,14,0.12)` + texto `#8A5E0E`): passa por pouco, mas o badge neutro de `05 §2.2` usa fundo `accent-soft` para contagem meramente informativa.** Informação neutra em dourado de marca dilui o sinal (HIG: accent = ação/marca, não "qualquer número"). AJUSTE: badge de contagem default = neutro (`--bg-2` fundo + `--text-1` texto + `tabular-nums`); dourado só para contagem que exige ação; `danger-soft/danger` para alerta. `05 §2.2` reescrito nesse sentido.

### 1.2 Touch < 44px (HIG 44pt; WCAG 2.5.8 mínimo 24px — HIG manda 44)
- **B-07 (falsa matemática do "pitch 44px").** `05 §2.4` declara item 40px + gap 4px = "alvo HIG 44pt". Falso: área tocável é 40px, gap não é tocável. **Viola HIG.** O mesmo doc trava toggle de colapso `32×32` e botão `…` do footer `32px`. `06 §1.1` trava `.btn {min-height:36px}`, `sizes md h-9 (36px)`, `.btn-icon ~36px "elevar p/ 44 no DS"` (promessa, não valor), input `min-height:40px`, tabs `padding .6/.9rem (~38px)`, segmented `~30px`. AJUSTE (todos, sem exceção): item de nav `44px` (desktop e mobile, sem dois valores); toggle colapso `44×44`; botão footer `44×44`; `.btn` default `h-11 (44px)` — `h-9` vira `size="sm"` permitido **só** em toolbar densa com alvo vizinho ≥8px e nunca em ação primária/destrutiva; `btn-icon` `44×44`; input/select/textarea `min-height:44px`; tab `min-height:44px`; segmented `min-height:44px`; checkbox nativo embrulhado em label com área `44px`. `07 §1` `sizes` reescrito: `md: h-11`, `sm: h-9 (restrito)`, `icon: h-11 w-11`.
- **B-08 (dot de badge colapsado 8px).** `05 §2.2`: dot 8px sem texto. 8px é invisível para baixa visão e não tem contraste 3:1 garantido. AJUSTE: dot `10px` com borda `2px solid var(--bg-1)` + `aria-label` sempre no link (não só quando há badge) + tooltip Radix com a contagem.

### 1.3 Foco (três specs diferentes = nenhuma spec)
- **B-09.** `01`/`05`: `box-shadow: 0 0 0 2px var(--bg-1), 0 0 0 4px var(--focus)`. `03 §1.3`: `outline: 2px solid var(--accent); offset 2px`. `06 §1.1`: `outline 2px accent offset 2px` no botão, mas `06 §1.2` no input usa `border accent + outline 2px offset 1px`. Três anéis distintos. AJUSTE: **um** token, `--ring: 0 0 0 2px var(--bg-1), 0 0 0 4px var(--focus)` publicado em `01 §3` + classe `.ring-focus` (sem arbitrary `shadow-[...]` — ver B-24). Halo `var(--bg-1)` só vale sobre fundo sólido da página; **sobre glass/modal/menu o halo passa a `2px solid #000` em dark / `#FFF` em light** (contraste do anel ≥3:1 contra o backdrop real, 1.4.11). Foco aparece em ≤100ms, sem fade. `:focus:not(:focus-visible)` sem anel (mouse), `:focus-visible` sempre com anel (teclado). `forced-colors: active`: `outline: 3px solid ButtonText; outline-offset: 2px` (nenhum doc cobre — ver B-19).
- **B-10 (04 §3.4: "foco move DEPOIS da animação").** Modal abre (240ms) e só `onAnimationComplete` move o foco = usuário de teclado fica 240ms com foco atrás do overlay, leitor de tela lê fundo bloqueado. **Viola 2.4.3.** AJUSTE: foco move **sincronamente** na abertura (`requestAnimationFrame` / `initialFocus`, antes ou junto do primeiro frame), trap de foco ativo desde o mount; animação é só visual. Reescrever `04 §3.4` item 1 e o exemplo `§2.1` (`autoFocus`/`initialFocus` imediato, não `onAnimationComplete`).

### 1.4 Hierarquia por cor (a regra-mãe que os próprios docs quebram)
- **B-11 (`th` 600 vs `td` 400, mesma cor-família, mesmo 15px).** `02 §3.4`/`§4`: distinção header×célula = peso 400→600 em Segoe UI low-dpi, que renderiza quase igual. Peso sozinho nesse delta é sinal fraco. AJUSTE: `th = 12.5px/700 uppercase +0.06em --text-2` vs `td = 15px/400 --text-1` (tamanho + caixa + peso = triplo cue). Atualizar `02 §4` linha do `th` e `06 §1.3` (que ainda diz `th 600 dim 15px`).
- **B-12 (KPI currency mono × number sans).** `02`: mesmo tipo de dado (número grande) em duas fontes por "ritmo de leitura" opinativo. Quebra escaneabilidade e `tabular-nums` consistente. AJUSTE: ambos mono + `tnum`; diferença number×currency = prefixo `R$` + `data-kind`, nunca família.
- **B-13 (ghost sem borda idle).** `06 §1.1` ghost = texto `text-dim` transparente, affordance só no hover. Estado idle sem fronteira viola 1.4.1 (ação identificável só por posição). AJUSTE: ghost idle mantém `1px solid transparent` + texto `--text-1` (não dim); hover adiciona `background border-subtle` + borda `border-medium`. Ação terciária em tabela ganha `aria-label` + tooltip, nunca ícone nu sem nome.

### 1.5 Dark/light sem paridade
- **B-14 (specular oposto sem teste).** `01 §2`: specular dark `inset branco 10%`, light `branco 70%` — o de light sobre card branco é invisível e o de dark sobre modal pode estourar. Paridade exige teste em fundo real. AJUSTE: manter valores mas adicionar teste de aceite "specular visível sem reduzir contraste do título (medir antes/depois)".
- **B-15 (shadow dourada zumbi).** `03` regra 1 veta sombra colorida e manda migrar `globals.css:613`; `07 §1.4` **reintroduz** `auth-logo: 0 4px 18px rgba(232,179,75,.35)`. AJUSTE: deletar `auth-logo` colorida; logo usa `0 4px 18px rgba(0,0,0,.35)` nos dois modos (exceção de marca, se exigida, vai para `docs/decisoes` com foto, não para o config).
- **B-16 (scrim sem token, três valores).** `01`: scrim modal `.45/.30`; `05`: drawer scrim `.45`; `06`: overlay `.6`. AJUSTE: publicar `--scrim: rgba(0,0,0,.55)` dark / `rgba(15,17,21,.35)` light em `01 §3`; os três docs passam a referenciar `var(--scrim)`.

### 1.6 Micro 12.5px e dourado como única codificação
- **B-17 (piso incoerente).** `02 §3.3`: "Piso: 11px. Nada abaixo de `micro` (12.5px)" — 11 ≠ 12.5, e `05` usa 11px no grupo. AJUSTE: piso absoluto `12px`; `micro` 12.5px/700 (sobe de 600 para compensar corpo pequeno); rótulo de grupo 12px/700 `--text-2` (B-03); proibido qualquer `10–11px` inclusive `dots`/eixos de gráfico (eixo usa `12px --text-2`, Y `R$Xk` mantido).
- **B-18 (dourado = texto + fundo + borda + indicador + gráfico + foco).** Quando tudo é dourado, nada é dourado (HIG: accent com parcimônia). AJUSTE: dourado reservado a (1) CTA primário, (2) item ativo, (3) foco, (4) link. Contagem neutra, eixo de gráfico secundário e borda de card **não** usam accent (B-06; gráfico: receita `#46a758`/despesa `#e5484d` ok, tendência usa `--info` em vez de accent para não colidir com CTA).

## 3. Reduced-motion / transparency: cobre de verdade ou é enfeite?

**Veredito: esqueleto bom, acabamento de enfeite.** `01 §5`, `04 §3.2`, `05 §4.4`, `06 §2.3`, `07 @layer base` citam as media queries, mas com furos que quebram o recurso na prática:

- **F-01 (três mecanismos, nenhum dono).** `MotionConfig reducedMotion="user"` (04/05) + hook `useSafeTransition` (04 §3.2) + `@media reduce` no CSS (06/07) coexistem sem hierarquia. AJUSTE: `MotionConfig` é o dono para framer-motion; CSS cobre `animate-shimmer/shake/spin` + `scroll-behavior`; hook `useSafeTransition` **deletado** (duplica o MotionConfig e convida bypass). `scrollIntoView` sempre `behavior: "auto"` (nunca `smooth` sem checar a query) — `05 §4.3` corrigido.
- **F-02 (valores de fallback divergem).** `03` regra 9: "blur para 4px + elevação −1"; `01 §5`: "desligar blur globalmente (fallback sólido)"; `07`: `.glass → solid + backdrop-filter:none`. 4px de blur ≠ desligado, e "cair 1 nível" é inventado. AJUSTE: `reduce-transparency` = blur `0` + fundo `--surface-solid` em **tudo** (sidebar, topbar, card, modal, scrim mantém alfa? não — scrim vira `rgba(0,0,0,.6)` sólido dark). Deletar a regra do "4px / −1 nível".
- **F-03 (cobertura parcial).** Nenhum doc desliga: stagger de lista (04 `staggerList` continua com duration 0? MotionConfig zera, mas o `delayChildren` + opacity instant ainda atrasa leitura — travar: com reduce, lista renderiza sem variantes), shake (04 diz OFF — ok, mas o keyframe Tailwind `shake` de 07 só é anulado via `.animate-shake`, e o exemplo de `CodeInput` sugere `<m.span> shake` — unificar no mesmo kill-switch), `whileHover y:-1` (micro-movimento — desligar), countdown do toast (04 §3.2 diz "sem barra, fica até dispensar" — certo, mas 03/05 não repetem; replicar), animação do gráfico recharts (zero menção — travar `isAnimationActive={!reducedMotion}` no `ProjectionChart`), skeleton shimmer (06 ok, 07 ok — ligar os dois), drawer drag elástico (com reduce, `drag={false}`).
- **F-04 (transparency além do `.glass`).** `07` só trata `.glass`; badges `*-soft` translúcidos, scrim, overlay do drawer e `accent-soft` da pill continuam translúcidos em `reduce-transparency`. AJUSTE: na query, `*-soft` viram fundo sólido equivalente (`--bg-2` + borda da cor forte), scrim vira opaco (valor acima), pill ativa ganha borda `1px solid var(--accent-strong)` para não depender do wash.
- **F-05 (sem protocolo de teste).** Só `05` item 7 cita o teste. AJUSTE: UAT global (copiar para `01 §5`): (1) SO com "reduzir movimento" + "reduzir transparência" ligados, (2) DevTools emulate, (3) colapsar sidebar 10×, abrir modal/drawer/command-K, disparar erro de form, observar polling da projeção — nenhum vestígio de slide/fade/shake/blur; foco nunca perdido.
- **F-06 (ausências totais).** `prefers-reduced-data` (polling de projeção `08` F7 sem backoff/stop — travar: polling com limite 10 tentativas + botão "Parar" + respeita `Save-Data: on` desligando polling automático), `forced-colors` (zero menção nos 8 docs — adicionar bloco: `forced-color-adjust`, `ButtonText/CanvasText`, indicador ativo vira `border-left`, charts com `fill: CanvasText`), e `prefers-contrast: more` (subir `border-medium→strong` automaticamente — 3 linhas de CSS, incluir).

## 4. Veredito por doc + AJUSTES OBRIGATÓRIOS
